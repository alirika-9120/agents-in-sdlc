アプリケーションの最も単純な更新でも、複数のファイルを変更し、テストを実行するなどの作業が必要になることがあります。開発者は、必要なファイルを見つけ、変更を加え、テストを実行し、デバッグし、変更し忘れたファイルを見つけて、さらに更新するという作業を繰り返します。

このようなときに役立つのが Copilot Agent Mode です。

Copilot Agent Mode は、IDE 内でより自律的に作業します。開発者と同様に、まず既存のプロジェクト構造を調べ、必要な変更を行い、テストなどのタスクを実行して、見つかった問題を自動的に修正します。Agent Mode を使ってサイトに機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェント モードと cloud agent は異なる用途向けに作られています。エージェント モードは IDE 内で動作し、すばやいフィードバックと対話ができます。cloud agent はチームの一員のように非同期で作業し、Issue やプルリクエストを通じてやり取りします。

この演習では、次のことを学びます。

- Copilot Agent Mode がプロジェクトを調べ、関連ファイルを特定し、複数ファイルを連携して変更する方法
- GitHub Copilot Agent Mode が UI とデータレイヤーにまたがる新機能を実装する方法
- コードベースにマージする前に、Copilot Agent Mode が生成した変更とテストをレビューする方法

## シナリオ

ゲームの一覧が増えてきたため、利用者がカテゴリとパブリッシャーで絞り込めるようにします。前の演習ではパブリッシャー ヘルパーを追加しました。次は、Copilot Agent Mode を使って残りのデータレイヤー、UI、テストを完成させます。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、Tailspin Toys の現在の機能を確認します。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディング プラットフォームです。ゲームの一覧や詳細を表示できます。単一の Astro アプリであり、ビルド時に静的 HTML としてページをレンダリングします。ページは frontmatter 内で Drizzle ORM を使ってローカル SQLite データベースを直接クエリします。別のバックエンド API やクライアント側 UI フレームワークはありません。再利用可能なデータ アクセス ヘルパーは `src/lib/` にあり、インタラクティブな動作には標準の DOM API を使う小さな Astro `<script>` を使用します。

### Web サイトを起動する

単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace で次の手順を実行します。

1. Codespace に戻ります。前の演習の後で `main` に戻っているはずです。
2. Codespace 内で <kbd>Control</kbd>+<kbd>`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>`</kbd> (Windows/Linux) を押して、新しいターミナルを開きます。
3. フィルター機能用のブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーが起動すると、次のような URL を示すバナーが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くよう促すダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を、<kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら選択して、Web サイトを開きます。

> [!NOTE]
> Codespace のターミナルで localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` にリダイレクトされます。これは、Web サーバーを実行している Codespace へのプライベート トンネルです。

### Web サイトを確認する

Web サイトを起動したら、機能を確認します。主な機能は次のとおりです。

- **ホーム ページ**: タイトル、画像、説明を含むボードゲームの一覧を表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、パブリッシャー、カテゴリなどの詳細ページが表示されます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 以下の演習を始める前に、Codespace に戻り、Copilot Chat パネルを開いて **New Chat** を選択し、新しい会話を開始します。演習ごとにモードとモデルの選択が異なります。必要な場合は、各手順で説明します。

Web サイトの初期実装は動作しますが、新しい機能を追加しましょう。まず、バックログを確認します。テンプレートからプロジェクトをセットアップすると、Issue のバックログも自動的に作成されています。GitHub Copilot に一覧を表示するよう依頼します。

1. Chat ビューのエージェント選択メニューで **Agent** を選択します。**Agent** は、ファイルをまたぐ変更を自律的に計画・実装し、ターミナル コマンドを実行してツールを呼び出します。

   ![Chat ビューのエージェント選択メニューを示すスクリーンショット](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者が特定のモデルを推奨するものではありません。ワークショップの作成時に Claude Sonnet 4.5 を使用したため、手順に含めています。提案されるコードに一貫性を持たせ、よい体験を提供することが目的です。ただし、LLM の動作は確定的ではないため、ワークショップの例とは異なる提案が出る場合があります。これは通常の動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の MCP コマンドを使う場合がありますが、タスクは完了できます。

3. 次のプロンプトを Copilot に送信して、Issue のバックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。利用者にとって特に役立つものを優先して、Issue の順序を決めるのを手伝ってください。
   ```

4. **Continue** を選択して、すべての Issue を一覧表示するコマンドを実行します。
5. 生成された Issue の一覧を確認します。

Copilot が利用者に役立つと思われる項目を優先順位付けしたことも確認できます。

## 指示ファイルを確認する

Copilot にコードを生成させる前に、作業のコンテキストを与える指示ファイルを確認します。Web サイトの機能追加の進め方を説明する [user interface (UI)][ui-instructions] ファイルを使います。

1. Codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能追加のガイダンスを確認します。次の内容が含まれています。
   - アーキテクチャの概要
   - コンポーネントの設計、テスト容易性、アクセシビリティに関する原則
   - Astro、Tailwind CSS、Drizzle などのファイル種別に応じた指示ファイルへのリンク

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルの場所からの相対パスです。指示を再利用し、複雑な内容を管理しやすい小さな単位に分け、例やテンプレートを示せます。

## フィルター機能を実装する

フィルター機能を完成させるには、少なくともアプリケーションに3つの変更が必要です。

- データレイヤー (`src/lib/`) にフィルター ロジックを追加または調整する
- フィルターの動作を確認するテストを追加または更新する
- ゲーム一覧ページにフィルター UI を追加する

さらに、コードベースにマージする前にテストを実行して成功させる必要があります。Copilot Agent Mode にこれらの作業を依頼しましょう。

1. Copilot との現在の会話を続けるか、**New Chat** を選んで新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択し、指示ファイルを追加します。

   ![UI 指示ファイルを選択する例を示すスクリーンショット](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント選択メニューで **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択メニューを示すスクリーンショット](../../../_images/shared-chat-mode-selector.png)

4. モデルに **Claude Sonnet 4.5** が選択されていることを確認します。
5. バックログの関連 Issue の要件に基づいて機能を実装するよう、次のプロンプトを Copilot に送信します。

   ```plaintext
   関連する GitHub Issue の要件に基づいて、サイトにパブリッシャーとカテゴリによるフィルター機能を追加してください。前の演習で追加したパブリッシャー ヘルパーを維持し、必要に応じて改善しながら、残りのデータレイヤー、UI、テストを完成させてください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、必要な機能に関連するファイルを特定する様子を確認します。データレイヤーのヘルパー、UI、テストを見つけて変更を始め、テストを実行します。

   ![Copilot がプロジェクト ファイルを調査する様子を示すスクリーンショット](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行などを行います。タスクやコードベースの複雑さによって、数分かかる場合があります。作業中にコード エディターで **Keep** と **Undo** のボタンが表示されることがあります。Copilot の作業中に選択する必要はありません。完了後、すべての変更に **Keep** または **Undo** が表示されます。

7. Copilot から求められたら、**Continue** を選択してテストを実行します。

   ![Copilot Chat がテスト実行の許可を求めるダイアログを示すスクリーンショット](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストが失敗したりする場合があります。問題ありません。Copilot はコード生成とテストを繰り返し、エラーを検出しなくなるまで作業を続けます。

   ![Copilot Agent Mode のセッション完了画面を示すスクリーンショット](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot やほかの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを実行しているブラウザーに戻り、新機能を確認します。
11. すべて正常に動作し、コードのレビューも完了したら、Copilot Chat ウィンドウで **Keep** を選択します。

## まとめと次のステップ

GitHub Copilot Agent Mode を使って Tailspin Toys の Web サイトに機能を追加する方法を学びました。この演習では、Agent Mode が UI とデータレイヤーにまたがる機能を実装し、プロジェクトを調べ、関連ファイルを特定して一貫した変更を行うこと、そしてコードベースにマージする前に変更とテストをレビューすることを確認しました。

次は、[Playwright MCP サーバーで機能をテストし][next-lesson]、プルリクエストを作成します。

### おまけの演習 — ページ分割を実装する

ゲームの一覧が増えると、ページ分割が必要になります。この演習で学んだことを使い、Copilot にページ分割の実装を依頼してみましょう。次の点を検討してください。

- 既存の指示ファイルを使うなど、現在のベスト プラクティスに従う。
- 利用者がページ サイズを選べるようにするか、固定値にするかなど、ページ分割の方法を決める。
- 希望どおりの実装を得るために必要なガイダンスを、プロンプトに含める。
- 変更を依頼したりコンテキストを加えたりしながら、Copilot と反復する必要がある場合もあります。これは Copilot を使う通常の作業方法です。

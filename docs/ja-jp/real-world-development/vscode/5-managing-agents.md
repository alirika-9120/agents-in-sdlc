GitHub Copilot をエージェント モードにすると、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または破棄し、エディターを離れずに追加のプロンプトを送って作業を調整または拡張できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- 作業中のセッションに指示を送り、ハイ コントラストに加えてライト モードのトグルを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けのライト モードのトグルも追加したいという要望がありました。新しい会話を始める代わりに、既存のセッションに指示を送り、作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイル編集は、差分と **Keep** / **Undo** の操作とともにチャットにインラインで表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール操作を確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライト モードを追加してもらう

ハイ コントラスト モードができたら、同じ会話でライト モードのトグルも追加します。同じチャット セッションを続けるので、エージェントは以前の作業、変更したコンポーネント、スタイルの方針、ローカル ストレージの使用方法などのコンテキストを保持しています。

1. Copilot Chat の入力欄に次のフォローアップ プロンプトを送信します。

   ```plaintext
   いいですね。次はハイ コントラストのトグルに加えて、ライト モードのトグルも追加してください。ライト モードも同じ方法で実装し、設定をローカル ストレージに保存して、同じ UI 領域から切り替えられるようにしてください。ハイ コントラスト モードとライト モードは、それぞれ独立して有効にできるようにしてください。
   ```

2. エージェントはすでに行った変更を調べ、そこから作業を続けてライト モードを追加します。
3. ハイ コントラスト モードと同様に、追加された編集をレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. 望まない方向に進んだ場合 (たとえば、好みでない方法でトグル UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足のメッセージを送信します。

> [!TIP]
> 作業中のセッションに指示を送る方が、最初からやり直すより短時間で済みます。フォローアップ プロンプトを使って、「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」のように調整を依頼できます。「3つ目のトグルを追加せず、ライト モードを既存の設定パネルに組み込む」のように方針を修正したり、「両方のトグルにキーボード ショートカットも追加する」のように範囲を広げたりすることもできます。

## 変更ファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティの指針 (ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージへの保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、作業中のセッションを監視し、方向を調整しました。ファイル編集を個別にレビューし、承認または破棄して、コンテキストを失わずに作業を拡張するフォローアップ プロンプトを送りました。

このレッスンでは、エージェントの作業をリアルタイムで監視し、ファイル編集を個別に承認または破棄し、作業中のセッションに指示を送る方法を学びました。

これまでに `quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザー上のフィルター操作を確認しました。次は、明確な QA プロセスを持つカスタムエージェントに、これらの機能をまとめます。

このレッスンでは、次の操作を行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルター機能の Issue に照らして結果を確認します。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト範囲、ブラウザーでの動作を一貫して確認したいと考えています。カスタムエージェントが QA プロセスを調整し、再利用可能なレポートを作成します。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の専門的な役割です。プロファイルには目的、指示、利用できるツールを記述します。このワークショップでは `.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまで使用したカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明し、`quality-checks` スキルは繰り返し実行できるチェックをまとめ、Playwright MCP はブラウザーツールを提供します。QA プロファイルは、それらを使って要件を評価し、結果を報告するよう Copilot に指示します。既存の機能に代わるものでも、別の会話を必要とするものでもありません。

## QA プロファイルを作成する

機能の PR を開く前に、Copilot に再利用可能な QA プロファイルを作成してもらいます。プロファイルには、QA が行うチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルター機能の会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。Issue と合意した要件に照らして機能を確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、テスト範囲が不足している場合はテストを追加する必要があります。

   各要件について、根拠を添えて成功、失敗、またはブロックとして報告させてください。実装コードを変更する前に必ず確認を求め、変更をコミットしたり、プルリクエストを開いたりしてはいけません。

   まずはレビューできるよう、プロファイルの作成だけを行ってください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA の作業手順と境界がプロファイルに含まれていることを確認します。これにより、検証だけを依頼したのに不完全なエージェントや範囲の広すぎるエージェントが機能を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須です。`name` は任意ですが、設定するとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件を出発点にし、リポジトリの指示に従い、`quality-checks` スキルと Playwright MCP を使うことを確認します。
4. QA が根拠を示し、実装コードを変更する前に確認を求め、変更をコミットしたり PR を開いたりしないことを確認します。
5. これらの責任や境界が欠けている場合は、続行する前に既定のエージェントに修正を依頼します。

## Issue を基に QA を実行する

Copilot CLI は、会話を開始するときにプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルター機能の会話を再開し、QA を選択すると、すでにある Issue と計画時の判断を利用できます。

1. 次のプロンプトを使ってエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成したばかりのエージェントは、利用可能なエージェントの一覧にまだ表示されない場合があります。その場合も、上記のコマンドで有効にできます。

2. 次のプロンプトで、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   Issue と計画で決めた内容に照らして、フィルター機能をレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントが作業を行います。
4. 完了したら、エージェントのレポートを読みます。

## まとめと次のステップ

再利用可能な専門的役割を追加し、その動作を確認しました。このレッスンでは、カスタムエージェントと指示、スキル、MCP ツールの連携を確認し、QA プロファイルを作成して、Issue に照らした結果をレビューしました。

これで、実装、スキルの更新、QA プロファイル、テスト、検証レポートがそろいました。次は、[変更を機能 PR にまとめ、Agent Merge を使います][next-lesson]。
